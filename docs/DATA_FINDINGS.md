## API и файлы

```python
from candidate_engine import generate_candidates
candidates = generate_candidates(profile, history, tariffs, config=None, trace=[])
```

Аргументы — DataFrame из `customer_profile.csv`, `data/change_tariff.csv`, `data/dict_tariff.csv`. Результат — новые словари со всеми обязательными полями контракта. `history=None` или пустая история включают каталог. Неполная схема непустого входа вызывает понятный `ValueError`. Для каталога обязательны `tariff_plan_code`, `price_tariff`; пакетные колонки необязательны. Пустой профиль, отсутствие альтернатив или `candidate_limit=0` дают `[]`.

Настройки: `candidate_limit=40`, `shrinkage_strength=50.0`; посторонние ключи игнорируются. Лимит должен быть целым неотрицательным, сила shrinkage — конечной неотрицательной. Функция не читает файлы, среду, мок-эффекты или другие командные модули, не меняет входы и не использует сеть. `trace` получает только агрегаты без ID абонентов; допускается строгая сериализация JSON.

## Робастный prior и единицы

Контекст определяется только по **доходу до смены**: LOW < 1000, MID от 1000 до 5000 включительно, HIGH > 5000. Числовые строки приводятся к числам. Из оценки исключаются нечисловые/бесконечные суммы, pre ≤ 0, неизвестные или пустые тарифы, self-переходы и переполнение относительного изменения.

Сырая величина: `raw_lift = (next - prev) / prev`. В пригодной истории медиана равна **0.01398185**, среднее — **450.36933120**, максимум — **592 276**, минимум — **−1**. У **2 558** строк абсолютное изменение превышает 1. Поэтому сырое среднее непригодно как основной критерий ранжирования.

Сначала каждый lift ограничивается интервалом [−1, 1]. При ≥20 пригодных наблюдениях дополнительно применяются общие квантили 1%/99% уже ограниченного ряда; интервал включает ноль. Если квантиль уничтожил бы редкий отрицательный или положительный знак, на соответствующей стороне сохраняется исходная граница −1 или 1. На этом пакете итоговые границы остались [−1, 1]. Это фиксированное правило устойчивости, не результат подбора по мок-эффектам.

Для точной исторической ячейки берётся среднее ограниченных изменений:

```text
prior_lift = robust_mean_lift × n / (n + shrinkage_strength)
prior_score = served_arpu × prior_lift × (0.5 + 0.5 × positive_rate)
```

`prior_lift` — безразмерная доля изменения среди исторических сменивших тариф; 0.20 означает 20%, а не 0.20%. Отрицательные значения сохраняются. `positive_rate` — доля строго положительных сырых изменений среди пригодных записей, **не вероятность конверсии**. `raw_mean_lift`, `raw_median_lift`, `robust_mean_lift` сохранены как дополнительные диагностические поля. Пилоты не должны интерпретировать исторический n как размер своей выборки.

`audience_arpu` и `served_arpu` — суммы прогнозной выручки в условных единицах. `audience_size` — размер полной валидной ячейки, `served_size` — min(5000, размер). Выбираются первые 5000 строк по **числовому ID_NUMBER**, а не по максимальной выручке. В текущем пакете ни одна ячейка не достигает 5000; ограничение проверено отдельно на искусственной ячейке из 5010 строк.

## Каталог и разнообразие

Для перехода без пригодной точной истории возвращаются `source="catalog"`, `history_count=0`, `prior_lift=0.0`, `positive_rate=0.5`. Ранжирование использует отдельную эвристику:

```text
price_similarity = exp(−abs(log(1 + target_price) − log(1 + current_price)))
package_retention = mean(min(target_package / current_package, 1))
plausibility = price_similarity × (0.5 + 0.5 × package_retention)
prior_score = served_arpu × 0.025 × plausibility
```

Учитываются известные текущие пакеты с положительным размером: интернет и две колонки минут. При отсутствии таких пакетных данных используется только цена. Неизвестная/отрицательная/бесконечная цена оставляет тариф допустимой целью, но его каталожная эвристика равна нулю. Противоречащие друг другу дубликаты кода тарифа вызывают ошибку. Номер тарифа не участвует в эвристике; при равенстве используется лексикографический `candidate_id`.

Коэффициент **0.025** задаёт только масштаб рейтинга для слабой каталожной гипотезы, не подменяет `prior_lift` и не означает ожидаемый рост на 2.5%. Это простая калибровка: уверенный положительный исторический сигнал обычно выше каталожного при одинаковой аудитории. Отрицательный исторический сигнал остаётся отрицательным. Все оценки — приоритет эксперимента, не валидированная прибыль.

Сначала выбирается до одного исторического лидера на ячейку, оставляя около 20% лимита под каталог. Каталог сначала покрывает ещё не выбранные ячейки, затем может добавить вторую альтернативу. Остальные места заполняются в порядке score с приоритетом новых ячеек; максимум две цели на ячейку. При лимите 1 отдельного резерва нет; при нехватке ячеек результат может быть короче лимита. Итог всегда отсортирован по убыванию score, затем по ID.

На данном пакете возможно **1260** не-self гипотез. Возвращены **40** кандидатов для **40** ячеек, из них **8** каталожных. Ограничения мешают большой ячейке или выбросу занять весь пул, но не гарантируют оптимального покрытия или качества скрытых эффектов.

## Ограничения для интегратора

- История отражает выбор сменивших тариф и другую популяцию. Ни causal uplift, ни конверсия по этим данным не обучаются; объединения с переходами других сегментов нет.
- Исключение невалидных ID/выручки происходит локально. Публичные фильтры кампании не умеют исключать отдельные плохие строки внутри валидной ячейки; на других данных возможна разница со скорером. В исходном профиле плохих ID/выручки нет.
- Повторные ID профиля не удаляются, считаются строки/контакты; при равных ID выручка используется только для детерминированного разрешения равенства. Дедупликация результата скорером может изменить денежный эффект. В исходном профиле повторов нет.
- Ограничение lift может занижать настоящие большие изменения. Эвристика каталога и квоты разнообразия — простые приоритеты, их качество на новой аудитории выясняется пилотами.
- Пилоты, портфель, `Agent.act`, benchmark и submission принадлежат другим ролям. Здесь не заявляется результат local_eval или прибыль на скрытых эффектах.
