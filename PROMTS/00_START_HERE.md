# Adaptive Campaign Portfolio Agent — план на 3 часа

Это комплект рабочих заданий для трёх студентов. Сначала передайте всем одну и ту же версию этой папки и starter kit. Каждый открывает свой clone в Astra 6 с reasoning high, читает общий контракт и вставляет свой промпт. Промпты на английском для единых имён и интерфейсов; отчёт для защиты — на русском.

**Результат за 3 часа:** работающий агент, проверка на 10 seed, воспроизводимый submission.csv, понятный README и отчёт о решениях. Успех измеряем net gain, соблюдением ограничений и воспроизводимостью. Победу и результат на скрытых эффектах заранее обещать нельзя.

## Что улучшено в исходной идее

1. История ранжирует гипотезы, но не становится тысячами фиктивных наблюдений новой аудитории. Исторические смены тарифа не дают вероятность конверсии среди всех получивших предложение.
2. В пуле есть несколько вариантов для разных сегментов и небольшой резерв новых переходов из каталога. Агент не застревает на первых десяти исторических лидерах.
3. После разведки подтверждаем решения, где дополнительное измерение может изменить большой денежный результат. Самый высокий средний lift не всегда заслуживает следующий пилот.
4. Эффект и ошибка приводятся к одной шкале перед сравнением каналов. Для push/SMS/ads это обосновано открытой механикой скоринга; call в первой версии исключён из-за насыщения вероятности и стоимости.
5. Оптимизатор рассматривает несколько вариантов портфеля, а не только сортирует кампании по прибыли. Иногда два дешёвых действия лучше одного дорогого.
6. Бесплатный push может снизить выручку. Аварийный fallback маркируется как рискованный вынужденный выбор для требования 1–10 кампаний.
7. В отчёте разделены: историческая гипотеза, шумное наблюдение, оценка риска и фактический результат mock evaluation.

## Архитектура, которую действительно успеваем сделать

~~~mermaid
flowchart TD
    H[История и каталог] --> C[Кандидаты: shrinkage и разнообразие]
    P[Профиль аудитории] --> C
    C --> E[Адаптивные пилоты]
    E --> U[Средний эффект и неопределённость]
    U --> E
    U --> O[Портфель: каналы, бюджет, контакты]
    O --> A[1–10 финальных кампаний]
    C --> T[Журнал решений]
    E --> T
    O --> T
    T --> R[Отчёт для маркетингового аналитика]
~~~

Это агент последовательного принятия решений с идеями exploration/exploitation. Не называем MVP полноценной обученной contextual-bandit платформой или causal uplift-моделью.

## Как не мешать друг другу

- У каждого отдельный clone и своя ветка. Студент 2 — единственный интегратор.
- Отсутствующий модуль коллеги заменяется только test double внутри вашего теста. Не создавайте чужой production-файл.
- Зависимости рантайма: pandas, numpy и стандартная библиотека. pytest — для тестов. Не нужны сервисы, GPU, Docker, обучение нейросети или база данных.
- Обновления в чат только в контрольные точки или при реальной несовместимости контракта: SHA, файлы, команда теста, результат, известное ограничение.
- Капитан забирает конкретные опубликованные commits в свою ветку интеграции. Например, после git fetch origin: git cherry-pick <SHA_PRIOR>, затем git cherry-pick <SHA_PORTFOLIO>. При дальнейших исправлениях берёт только новые SHA.
- Капитан не редактирует чужой модуль во время активной работы владельца. Обычный баг исправляет владелец. В 155 минут владельцы явно передают финальные файлы капитану; после этого не пушат новые изменения без согласования.
- Не используйте git add .: добавляйте принадлежащие вам пути. Не включайте .env, ключи, venv, кэш и персональные данные в commits.
- Не делайте force-push, reset или переименование общих файлов. Не меняйте файлы организаторов, не переносите CSV.
- Код пишется сразу. Не нужно согласовывать каждую функцию, выбор контейнера или небольшое исправление. Изменение публичного контракта — единственное техническое согласование, которого стараемся избежать.

## Ключи и LLM

Ключи OpenAI/NVIDIA для первой версии не нужны. Алгоритм должен полностью работать без сети. Astra используется для разработки.

Если всё принято и осталось больше 20 минут, возможен необязательный Analyst Copilot: пересказывает готовый журнал решений, не меняет кампании и числа. Это не входит в обязательную работу трёх ролей. API-код, если появится, получает ключи из переменных окружения, имеет timeout и текстовый fallback; никогда не отправляет ключи в чат. Не подключайте два провайдера ради демонстрации.

## Проверенные внешние ориентиры

Wayfair описывает использование contextual bandits для маркетинговых решений и баланс исследования/использования. Это аналогия, не доказательство качества нашего агента: [WayLift](https://www.aboutwayfair.com/careers/tech-blog/contextual-bandit-for-marketing-treatment-optimization).

Causal uplift оценивает эффект коммуникации; одних записей о состоявшихся сменах тарифа для такого вывода недостаточно: [scikit-uplift guide](https://www.uplift-modeling.com/en/v0.3.2/user_guide/).
